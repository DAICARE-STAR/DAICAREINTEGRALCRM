# monica — integracion

Repo leído: `C:\Users\enzov\IA\personal\investigacion-erp\monica` (Monica, CRM personal en Laravel). Todas las rutas son relativas a ese repo. Solo lectura; nada copiado, todo descrito con palabras propias.

Resumen del alcance: la API REST es mínima (usuarios y bóvedas); la integración real de Monica es el estándar CardDAV/CalDAV (servidor y cliente) con vCard e iCal como formato de importación y exportación. ## Decisiones de diseño que se notan y su porqué

- **Integrar por estándar abierto en lugar de una API propia amplia.** Con CardDAV y CalDAV, el teléfono y el cliente de calendario del usuario hablan directo con la app sin código de cliente propio; la API REST se quedó en lo mínimo (`routes/api.php:18-24`). Es un CRM personal: el valor está en que los contactos aparezcan en la libreta del móvil.
- **Piezas pequeñas enchufables y ordenadas por entidad.** El atributo `Order` (`app/Domains/Contact/Dav/Order.php:9-27`) permite añadir soporte para un campo nuevo sin tocar el servicio central.
- **Dos identidades por registro (local y distante).** Evita que un UID ajeno choque con las claves locales y permite reconciliar (`app/Domains/Contact/Dav/Importer.php:81-88`).
- **La sincronización calcula diferencias por tiempo y borrado lógico, no por bitácora de cambios.** Simple, pero obliga a cargar todos los objetos de la colección en cada consulta (`SyncDAVBackend.php:74-79`). Limitación aceptada a cambio de no mantener un log de eventos.
- **Todo lo lento va a cola con lotes y fallos permitidos**, y un fallo aislado no frena el resto (`AddressBookSynchronizer.php:42-52`).
- **Servicios con validación y permisos declarativos** (`rules()` y `permissions()`, p. ej. `ImportVCard.php:68-104`): la misma lógica sirve para web, API, DAV y colas.
- **Errores de API con códigos numéricos propios** además del estado HTTP (`config/api.php:42`), pensado para clientes que no quieren depender del texto.
- **Idioma por usuario, no por instalación**, con varios detectores y lista permitida validada en servidor (`config/localizer.php:26-35`).

## No conviene copiar (y por qué)

- **Servidor DAV completo dentro de funciones serverless.** Monica usa una librería PHP madura y un servidor persistente (`app/Providers/DAVServiceProvider.php:42-90`); en TypeScript no hay equivalente y PROPFIND o REPORT casan mal con Netlify Functions. Mejor un servicio aparte o solo exportación `.vcf` e `.ics`.
- **Cálculo de cambios cargando todos los objetos de la colección** (`app/Domains/Contact/Dav/Web/Backend/SyncDAVBackend.php:74-79`, `:131-199`). Aceptable en un CRM personal; con miles de movimientos de ventas o inventario se necesita una versión monótona por fila y consulta SQL.
- **API REST de cobertura mínima** (`routes/api.php:18-24`): no sirve de modelo de alcance; TailorSuite necesita cuentas, contactos, actividades y luego documentos comerciales.
